术语表

以下定义基于原书作者 Nigel Poulton 的术语表，按主题分组整理。

架构与核心概念

术语含义
集群（Cluster）一组协同运行用户应用的工作节点和控制平面节点。
控制平面（Control plane）每个集群的大脑，包括 API、API 服务器、调度器、所有控制器等，运行在所有控制平面节点上。
控制平面节点运行控制平面服务的节点，通常不运行用户应用。高可用应部署 3 或 5 个。
工作节点（Worker node / Node）运行用户应用的节点，运行 kubelet、容器运行时和 kube-proxy。
数据平面（Data plane）集群中承载用户应用的工作节点。
集群存储（Cluster store）保存集群和应用状态的控制平面功能，通常基于 etcd，可单独部署成集群以获得更高性能和可用性。
etcd大多数集群用作集群存储的开源分布式数据库。
kubelet每个节点上的主代理：监视 API 服务器的新任务，并维持一条汇报通道。
kube-proxy每个节点上运行，实现把 Service 流量路由到 Pod 的底层规则。
云控制器管理器与底层云平台集成的控制平面服务，比如为 LoadBalancer Service 创建云负载均衡器。
控制器（Controller）以调和循环运行的控制平面进程，持续让观测状态匹配期望状态。
调和循环（Reconciliation loop）通过 API 服务器监视集群状态、确保观测状态匹配期望状态的控制器进程。
期望状态（Desired state）集群和应用「应该」是什么样子，比如某微服务要 5 个监听 8080 的副本。
观测状态（Observed state）也叫当前状态、实际状态：集群和应用最新的真实情况。
编排器（Orchestrator）部署和管理应用的软件。Kubernetes 是基于容器的微服务应用的事实标准编排器。
云原生（Cloud native）一种设计、构建和运行现代应用与基础设施的方式。作者认为能自愈、按需扩缩、滚动更新（可能还能回滚）的应用就是云原生的。
微服务（Microservices）把应用功能拆成各自独立的小应用（容器），通过 API 通信，协同组成完整应用的设计模式。
K8sKubernetes 的简写，8 代替 K 和 s 之间的 8 个字母，读作 “Kates”。

容器与运行时

术语含义
容器（Container）运行现代应用的轻量环境。每个容器是一个虚拟的操作系统，有自己的进程树、文件系统、共享内存等。一个容器运行一个应用进程。
容器运行时每个节点上负责拉镜像、启停容器等底层操作的软件，通常是 containerd 或 CRI-O。Docker 在 1.20 被弃用、1.24 移除支持。
containerd大多数集群使用的业界标准容器运行时，由 Docker 公司捐给 CNCF，读作 “container dee”。
CRI-O容器运行时，常见于基于 OpenShift 的集群。
CRI容器运行时接口，让运行时可插拔，按需选择最合适的运行时。
CNI容器网络接口，可插拔，第三方插件实现覆盖网络、BGP 网络等。
CSI容器存储接口，让第三方存储系统接入 Kubernetes；厂商的 CSI 插件以 Pod 形式运行在集群上。
服务网格（Service mesh）提供 Pod 间流量加密、增强的网络遥测和高级路由的基础设施软件，如 Consul、Istio、Linkerd。

工作负载

术语含义
PodKubernetes 上最小的调度单位。所有容器都必须运行在 Pod 里。Pod 提供共享的执行环境：IP 地址、卷、共享内存等。
init 容器在主应用容器启动前运行并完成的特殊容器，常用于检查或初始化环境。
Sidecar与主应用容器一起运行、为其增强功能的特殊容器。服务网格常以 sidecar 注入 Pod。
Deployment部署和管理一组无状态 Pod 的控制器，支持发布、回滚和自愈，借助 ReplicaSet 实现扩缩和自愈。
ReplicaSet以控制器形式运行，执行自愈和扩缩，被 Deployment 使用。
StatefulSet部署和管理有状态 Pod 的控制器，类似 Deployment，但面向有状态应用。
清单文件（Manifest file）保存一个或多个 Kubernetes 对象配置的 YAML 文件，提交给 API 服务器后即部署到集群。
标签（Label）用于分组的对象元数据，与标签选择器配合把 Pod 和更高层的控制器、Service 关联起来。
标签选择器（Label selector）用来确定要对哪些 Pod 执行操作。比如滚动更新时，只有匹配 Deployment 选择器的 Pod 会被替换。
注解（Annotation）可用于暴露 alpha/beta 功能或与第三方系统集成的对象元数据。
Namespace把一个集群划分成多个虚拟集群的方式，适合施加不同的配额和访问控制策略，不适合强隔离。

网络

术语含义
Service首字母大写。为 Pod 中的应用提供网络访问。放在一组 Pod 前面后，Pod 失败、扩缩、被替换都不会改变访问入口；可与云平台集成创建互联网负载均衡器。
Endpoints / EndpointSlice匹配 Service 标签选择器的健康 Pod 的最新列表，即 Service 会把流量发给谁。EndpointSlice 在大集群上性能更好。
Gateway API把外部流量路由到 Kubernetes 应用的原生框架，需要 Envoy、NGINX 等第三方实现。
Gateway用于部署和管理外部负载均衡器的 Gateway API 资源。
ListenerGateway 的属性。Gateway 代表负载均衡器，listener 代表它的接口，比如监听 8080 的 HTTP 流量。
GatewayClass把 Gateway 映射到某个 Gateway API 控制器。
Gateway 控制器监视并调和 Gateway 的控制平面进程。没有默认实现，需要安装第三方的。
HTTPRoute给 Gateway listener 编程高级路由的资源，比如把 example.com/kits 的 90% 请求发给 Service A、10% 发给 Service B。
Ingress已弃用，被 Gateway API 取代。

存储与配置

术语含义
卷（Volume）持久存储的泛称。
PersistentVolume（PV）在集群上映射存储卷的对象。外部存储必须先映射成 PV 才能被应用使用。
PersistentVolumeClaim（PVC）像一张允许应用使用 PV 的票据。没有有效的 PVC，应用就用不了 PV。与 StorageClass 配合实现动态创建卷。
StorageClass（SC）在集群上创建不同存储档位的方式，比如 fast 创建 NVMe 存储，medium-three-site 创建跨三个站点复制的慢速存储。
ConfigMap保存非敏感配置数据的对象，可在运行时给通用容器加入自定义配置而无需改镜像。
Secret用于敏感配置数据的「ConfigMap」，把敏感数据保存在镜像之外，运行时注入容器。

API 与安全

术语含义
API应用程序编程接口。Kubernetes 的所有资源都定义在 RESTful 的 API 中，通过 API 服务器暴露。
API 服务器在安全端口上通过 HTTPS 暴露 API，运行在控制平面上。
API 组一组相关的 API 资源，比如网络资源通常在 networking.k8s.io 组里。
API 资源Pod、Deployment、Service 等所有 Kubernetes 对象都以资源的形式定义在 API 中。
CRD自定义资源定义，用于向 Kubernetes API 添加你自己的资源。
REST表述性状态转移，最常见的 Web API 架构，用 GET、POST、PUT、PATCH、DELETE 等 HTTP 方法操作对象。
CRUD创建、读取、更新、删除四种基本操作。
JSONJavaScript 对象表示法，Kubernetes 首选的数据发送和存储格式。
YAML通常用来编写 Kubernetes 配置文件的语言，是 JSON 的超集。
kubectlKubernetes 命令行工具，通过 API 服务器发送命令和查询状态。
RBAC基于角色的访问控制，判断已认证用户能否对集群资源执行操作的授权模块。
准入控制器（Admission controller）验证或修改资源以执行策略的代码，在认证和授权之后作为 API 准入链的一部分运行。
