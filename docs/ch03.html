第 3 章

搭建 Kubernetes 环境

理论讲完了，该动手了。这一章准备好三样东西：Docker、一个 Kubernetes 集群和 kubectl 命令行工具。最后还会讲清楚 kubectl 是怎么知道「该把命令发给哪个集群」的。

本章目标

  • 用 Docker Desktop 在笔记本上跑起一个 3 节点的集群
  • 知道什么时候需要一个云上集群（Gateway API、存储章节）
  • 克隆本书的示例代码仓库
  • 理解 kubeconfig 文件里的 clusters、users、contexts 和 current-context

选哪种集群？

ⓘ 其他本地选择

除了 Docker Desktop，作者也常用 k3d、KIND 和 minikube 在笔记本上跑集群。 任何一个都可以，只是 Docker Desktop 的优势在于自带全套 Docker 开发工具并自动装好 kubectl。

用 Docker Desktop 一次装好

⚠ 许可证提示

Docker Desktop 对个人和教育用途免费。如果用于工作，且公司员工超过 250 人或年收入超过 1000 万美元，需要购买许可证。

  1. 到 app.docker.com/signup 注册一个免费的个人账号。
  2. 搜索 Docker Desktop，下载对应系统（Linux / Mac / Windows）的安装包，版本需要 4.60 或更新，一路「下一步」安装。Windows 用户在提示时安装 WSL（Windows Subsystem for Linux）。
  3. 启动后，Mac 菜单栏顶部 / Windows 系统托盘里会出现一只鲸鱼图标。

打开终端，确认 Docker 和 kubectl 都装好了：

$ docker --version
Docker version 28.3.3, build 309deef

$ kubectl version --client=true -o yaml
clientVersion:
  major: "1"
  minor: "35"
  platform: darwin/arm64

创建内置的多节点集群

  1. 点击鲸鱼图标并登录，然后打开 Settings。
  2. 在 General 标签页里确认勾选了 Use containerd for pulling and storing images，必要时点击 Apply & restart。
  3. 左侧导航选 Kubernetes，点击蓝色的 Create cluster，选择 kind（另一个选项 kubeadm 只能创建单节点集群）。
  4. 把 Node(s) 滑块拉到 3，选择最新版本，勾选 Show system containers (advanced)。
  5. 点击 Apply & restart，等一两分钟，界面底部出现绿色的 Kubernetes running 就好了。
$ kubectl get nodes
NAME                    STATUS   ROLES           AGE   VERSION
desktop-control-plane   Ready    control-plane   10m   v1.35.1
desktop-worker          Ready    <none>          10m   v1.35.1
desktop-worker2         Ready    <none>          10m   v1.35.1

回到 Docker Desktop 的 Containers 标签页，你会看到三个和节点同名的容器。 这是因为 Docker Desktop 用容器来模拟节点。别被它绕晕：对你来说，使用体验和真实集群完全一样。

在云上建一个集群（Akamai LKE）

LKE（Linode Kubernetes Engine）是 Akamai 云上的托管 Kubernetes 服务：集群由 Akamai 搭建，并负责可用性、性能和升级。 这类托管服务是你能得到的「几乎零成本维护的生产级集群」。其他云厂商也有类似服务（EKS、AKS、GKE……），都可以用， 只是本书的存储示例是按 Akamai 云存储写的，换云的话要改存储相关的配置文件。

创建集群

注册 Akamai 账号（书中提供了新用户 60 天 100 美元额度的推荐链接），然后到 cloud.linode.com → Kubernetes → Create Cluster，填写：

设置项取值
Cluster labeltkb
Region选一个离你近的区域
Kubernetes Version选一个较新的版本
Akamai API PlatformNo
HA Control PlaneNo（学习用不需要高可用控制平面）
Control Plane ACLDisabled
Node PoolsShared CPU 标签页，添加 3 × Linode 2GB 节点

点击 Create Cluster，等一两分钟三个节点都变绿，剩下的就是配置 kubectl 连上它。

⚠ 用完记得删集群

云集群按时间计费。做完需要它的章节后，到控制台把集群删掉，避免意外扣费。

kubectl 与 kubeconfig

kubectl 是 Kubernetes 的命令行工具，所有动手示例都要用它。 安装的版本应与集群版本相差不超过一个小版本：集群是 v1.35.x，kubectl 就应该在 v1.34.x 到 v1.36.x 之间。

每条 kubectl 命令背后发生了什么

kubeconfig 文件的结构

kubeconfig 文件名就叫 config（没有扩展名），放在家目录下的隐藏文件夹 .kube 里： macOS / Linux 是 ~/.kube/config，Windows 是 C:\Users\<用户名>\.kube\config。它定义了四样东西： 

apiVersion: v1
kind: Config
clusters:                       # 所有集群都列在这里
- name: shield                  # 集群的友好名字
  cluster:
    server: https://192.168.1.77:8443        # 集群 API 服务器地址
    certificate-authority-data: LS0tLS...    # 集群的 CA 证书
users:                          # 用户凭据列表
- name: coulson                 # 友好名字（Kubernetes 本身不使用）
  user:
    client-certificate-data: LS0tLS1CRU...   # 用户证书
    client-key-data: LS0tLS1CRUdJTiBFQyB     # 用户私钥
contexts:                       # context 列表（集群:用户 的组合）
- context:
    cluster: shield             # 把命令发到这个集群
    user: coulson               # 用这个凭据认证
  name: director                # 名为 director 的 context
current-context: director       # kubectl 默认使用的 context

常用的查看与切换命令：

$ kubectl config current-context
docker-desktop

$ kubectl config get-contexts
CURRENT   NAME             CLUSTER          AUTHINFO          NAMESPACE
*         docker-desktop   docker-desktop   docker-desktop
          lke349416-ctx    lke349416        lke349416-admin   default

$ kubectl config use-context lke349416-ctx
Switched to context "lke349416-ctx".

kubectl config view 可以查看完整配置（敏感数据会被隐藏）。装了 Docker Desktop 的话，也可以点鲸鱼图标 → Kubernetes Context 直接切换。

把云集群加进 kubeconfig

从 Akamai 控制台下载集群的 kubeconfig 文件（例如 tkb-kubeconfig.yaml）。分两种情况：

还没有 ~/.kube/config
  1. 在家目录创建隐藏文件夹 .kube
  2. 把下载的文件放进去
  3. 重命名为 config（不能带 .yaml 扩展名）
已经有 ~/.kube/config：合并
$ mv ~/.kube/config ~/.kube/config-bkp
$ export KUBECONFIG=~/.kube/config-bkp:~/.kube/tkb-kubeconfig.yaml
$ kubectl config view --flatten > ~/.kube/config
$ export KUBECONFIG=~/.kube/config
$ kubectl config use-context lke349416-ctx

测试一下：

$ kubectl get nodes
NAME                            STATUS   ROLES    AGE   VERSION
lke349416-551020-184a46360000   Ready    <none>   19m   v1.35.1
lke349416-551020-1c6f99c20000   Ready    <none>   19m   v1.35.1
lke349416-551020-47ad6c5c0000   Ready    <none>   19m   v1.35.1
★ 为什么一个控制平面节点都看不到？

三个节点的 ROLES 都是 <none>，说明它们都是工作节点。这是托管 Kubernetes 的特点： 控制平面由云厂商管理并对你隐藏。如果报错或节点名不是 lke 开头，多半是 kubeconfig 配置有问题，请回头仔细检查。

小结

  • Docker Desktop 一次装好 Docker、kind 多节点集群和 kubectl，适合大部分示例。
  • Gateway API 和存储章节需要云上集群，比如 Akamai LKE；用完要删除。
  • kubectl 把命令转换成 HTTPS REST 请求，发给 kubeconfig 中 current-context 指定的集群，并使用其中的凭据认证。
  • kubeconfig 由 clusters、users、contexts、current-context 四部分组成，context 就是「集群 + 用户」的组合。

动手练习

  1. 装好 Docker Desktop，创建 3 节点的 kind 集群，运行 kubectl get nodes 看到三个 Ready 节点。
  2. 运行 kubectl config view，在输出里找到 clusters、users、contexts 三段，说出你当前的 context 由哪个集群和哪个用户组成。
  3. 运行 kubectl get nodes -v=6，在详细日志里找到 kubectl 真正发出的 HTTP 请求 URL。
  4. 克隆本书仓库并切到 2026 分支，浏览一下目录结构。
