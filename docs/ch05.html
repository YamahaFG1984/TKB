第 5 章

Namespace：把集群切成虚拟集群

一个集群往往要给好几个团队、好几套环境共用。Namespace（命名空间）就是用来把一个物理集群 划分成多个虚拟集群的工具。这一章篇幅不长，但后面几乎每章都会用到它。

本章目标

  • 分清 Kubernetes Namespace 和 Linux 内核命名空间
  • 理解 Namespace 只提供软隔离，什么时候该用多个集群
  • 认识集群自带的 4 个 Namespace
  • 用命令式和声明式两种方法创建 Namespace、往里部署对象
  • 让 kubectl 默认操作某个 Namespace

两种「命名空间」，别搞混

本书把 Kubernetes 的 Namespace 首字母大写，以区别于内核命名空间。 每个 Namespace 可以有自己的用户、权限、资源配额和策略。但请牢记：Namespace 只提供软隔离—— 一个 Namespace 里被攻破的工作负载，很容易影响到其他 Namespace 里的工作负载。

哪些对象属于 Namespace？

大部分对象都是命名空间级的（可以部署到指定 Namespace）；少数是集群级的，比如 Node 和 PersistentVolume。用这个命令查看：

$ kubectl api-resources
NAME                     SHORTNAMES   APIVERSION   NAMESPACED   KIND
nodes                    no           v1           false        Node
persistentvolumeclaims   pvc          v1           true         PersistentVolumeClaim
persistentvolumes        pv           v1           false        PersistentVolume
pods                     po           v1           true         Pod
resourcequotas           quota        v1           true         ResourceQuota
secrets                               v1           true         Secret
serviceaccounts          sa           v1           true         ServiceAccount
services                 svc          v1           true         Service
...
💡 顺便学会简称

SHORTNAMES 一列是 kubectl 可用的简写：kubectl get po = kubectl get pods，svc = services，ns = namespaces。

Namespace 的使用场景

Namespace 是让多个租户（tenant）共享同一集群的方式。租户可以是应用、团队、部门，甚至外部客户。 最常见的是在同一组织内部划分，比如按组织架构把生产集群分成三个 Namespace：

★ 选择的经验法则

信任彼此的内部团队、开发/测试/预发环境 → Namespace。
互不信任的外部客户、强合规要求 → 独立集群 + 独立硬件（撰写本书时最常见的强隔离做法）。

创建和管理 Namespace

以下命令在仓库的 namespaces 目录执行。Namespace 是核心 v1 API 组里的一等资源，命令式和声明式都能用：

命令式：一条命令
$ kubectl create ns hydra
namespace/hydra created
声明式：YAML 文件（推荐）
kind: Namespace
apiVersion: v1
metadata:
  name: shield
  labels:
    env: marvel

$ kubectl apply -f shield-ns.yml
namespace/shield created

$ kubectl get ns
NAME     STATUS   AGE
...
hydra    Active   23s
shield   Active   11s

$ kubectl delete ns hydra        # 漫威里神盾局和九头蛇是死敌，别让它们共享一个集群
namespace "hydra" deleted

让 kubectl 默认使用某个 Namespace

每条命令都加 -n shield 很烦。更好的办法是修改 kubeconfig 当前 context 的默认 Namespace：

$ kubectl config set-context --current --namespace shield
Context "tkb" modified.

往 Namespace 里部署对象

两种方式：命令式在命令上加 -n；声明式在 YAML 的 metadata.namespace 里写明。来看 app.yml，它用 --- 分隔，在一个文件里定义了三个对象：

apiVersion: v1
kind: ServiceAccount
metadata:
  namespace: shield          # ← 目标 Namespace
  name: default
---
apiVersion: v1
kind: Service
metadata:
  namespace: shield          # ← 目标 Namespace
  name: the-bus
spec:
  type: LoadBalancer
  ports:
  - port: 8080
    targetPort: 8080
  selector:
    env: marvel
---
apiVersion: v1
kind: Pod
metadata:
  namespace: shield          # ← 目标 Namespace
  name: triskelion
  labels:
    env: marvel
spec:
  containers:
  - image: nigelpoulton/k8sbook:shield-01
    name: bus-ctr
    ports:
    - containerPort: 8080
    imagePullPolicy: Always

$ kubectl apply -f app.yml
serviceaccount/default configured
service/the-bus configured
pod/triskelion created

$ kubectl get pods -n shield
NAME         READY   STATUS    RESTARTS   AGE
triskelion   1/1     Running   0          59s

$ kubectl get svc -n shield
NAME      TYPE           CLUSTER-IP     EXTERNAL-IP   PORT(S)          AGE
the-bus   LoadBalancer   10.43.30.174   localhost     8080:31112/TCP   68s

$ curl localhost:8080

<head>

ⓘ Docker Desktop 的小坑

有些 Docker Desktop 集群会把 EXTERNAL-IP 错误地显示成 172.x.x.x，这时用 localhost:8080 访问即可。ServiceAccount 缺少注解的警告也可以忽略。

清理

$ kubectl delete ns shield              # 删除 Namespace 会连带删除里面的所有对象
namespace "shield" deleted

$ kubectl config set-context --current --namespace default   # 别忘了改回来！
Context "tkb" modified.
⚠ 删除 Namespace 是「连锅端」

它会删掉里面的 Pod、Service、ServiceAccount 等全部对象，在生产环境操作前务必三思。另外，如果不把默认 Namespace 改回 default，之后的命令会针对一个已经不存在的 Namespace，什么都查不到。

小结

  • Namespace 把一个集群切成多个虚拟集群，每个可以有自己的用户、RBAC 规则、配额和策略。
  • 它只提供软隔离，不能用于强多租户；强隔离需要独立集群和硬件。
  • 不指定时对象会进入 default；系统组件在 kube-system。
  • 用 -n 临时指定，用 metadata.namespace 声明式指定，用 kubectl config set-context --current --namespace 设置默认值。
